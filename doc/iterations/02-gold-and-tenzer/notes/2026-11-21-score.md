# Design note: the score

Status: agreed for iteration 2 (2026-11-21). Nothing here is
implemented. The goal of the iteration (typeset Gold's Jaya Semara and
Tenzer's Baris) and every decision are in `2026-11-21-iteration-2.md`,
which wins where the two disagree.

Related: `2026-11-21-notation-language.md` (the music),
`2026-11-21-internal-representation.md` (what the reader builds),
`../targets/2026-11-21-jaya-semara-pangecet.nts` and `../targets/2026-11-21-baris.nts`
(examples with scores).

## Considerations

### Music and score are different things

The notation language describes the music: what sounds and when. How it
is printed is a separate question, and today it is answered only by the
`group` form, a few display settings scattered through the music
(`show-names` on instruments, `steps-per-system` on the piece), and a
style set from Guile (`make-style`). We want a formal score syntax, so
that printing options can be switched on and off, and so that a part
can be defined but not printed.

### What LilyPond does

LilyPond is the model:

- Music is kept in variables. A `\score { ... }` block builds what is
  printed from that music, as a tree of contexts
  (`\new StaffGroup << \new Staff \polos ... >>`). Music that no score
  uses is not printed, but it still exists.
- One file can hold several scores, so the same music can be printed as
  a full score, an excerpt or a single part.
- Settings are inherited: `\layout { \context { \Staff ... } }` sets
  defaults for every staff, `\new Staff \with { ... }` overrides them
  for one. Features such as bar numbers are switched on and off this
  way.
- Each staff has a long and a short name: `instrumentName` on the first
  system, `shortInstrumentName` on the following ones.
- The header (title, composer) is separate from both music and layout.

### How the score should look

The typesetting is meant to be highly flexible, and the notation says
what is shown and how:

- Notes are drawn on a grid. By default a note is only a colour; note
  or stroke names are added only when asked for.
- Pattern names are written over the coloured notes, across the span
  of the pattern.
- Above the grid there can be the cycle number and/or the pulse number
  within the cycle, as chosen.
- On the left are the group labels, long or short, as chosen. The user
  writes both forms.
- The colour scheme, the font size and the grid size are chosen in the
  score.

The split of ADR 0005 stays: the notation chooses (a palette, a size),
Guile works out the values (hex colours, widths), and Typst only draws
them. What changes is that the choices come from the notation, not from
Guile code.

### A second target: Tenzer's Baris

Michael Tenzer's notation of Baris (gilak) is laid out very differently
from our coloured grid, and the score syntax must be able to typeset it
too (`../targets/2026-11-21-baris.nts`):

- Names only, no colour. The degrees are written as syllables: the
  open form when the note rings (`nang`), the damped form when it is
  cut short (`na'`).
- Only the reyong has a row per pitch. The ugal, calung, kempli and
  gongs each have one row, with the names as text; the gong and kempur
  share a row. Each drum has two rows, labelled LH and RH, one per
  hand.
- Beats are numbered with the gong as 1 (Gold puts the gong last), and
  the header row is labelled "Beats".
- The cycle is broken after beat 3, into systems of 3 and 6 beats.
- Below the figure, single parts are written as sung lines: one row,
  with "-" for each held step; and the four drum hands are combined
  into one composite row.
- Each block has a caption.
- Instrument pictures, "etc." at the line ends and the two halves side
  by side are left out for now.

The music itself needs nothing new: written in the notation, it expands
to exactly the strokes of the figure, for every part.

### Decisions so far

- A score is a form in the same file as the music.
- Group labels are written by the user, in a long and a short form; the
  score chooses which is printed.
- No level above groups for now (LilyPond's `StaffGroup` bracket).
- No tagged versions of the music for now (LilyPond's `\tag`).
- Tenzer's layout is copied in its information and arrangement; his
  instrument pictures, "etc." at line ends, colons after labels and
  systems side by side are left for later.

## The `score` form

```scheme
(score NAME :key value ...
  (group LABEL :key value ...  PART ...)
  ...)
```

It follows the conventions of the rest of the language: positional
arguments, then `:key value` options, then the body.

- NAME names the score, so a file can have several.
- The body is a list of groups, printed top to bottom in that order.
- A group is a block of rows sharing lanes, as before. LABEL is its long
  label; PART ... are the parts it shows.
- A part that is in no group of a score is not printed in that score.
  This is how a part is defined but not printed.
- Generated parts are named like any other: the timekeeper is `kempli`
  (or the colotomy's timekeeper), and each colotomy part has the name
  its colotomy gives it (`gong`).

## Options

A score option sets the default for all its groups; a group option
overrides it for that group, as `\layout` and `\with` do in LilyPond.
Options marked "score" can only be set on the score.

### Header and range

| Option | Level | Default | Meaning |
|---|---|---|---|
| `:title STRING` | score | the piece's title | Title. |
| `:subtitle STRING` | score, group | none | Subtitle; a group's subtitle is printed under its label. |
| `:from POS`, `:to POS` | score | whole piece | Print an excerpt, both ends included. POS is `(CYCLE PULSE)`, or a pulse number without a colotomy. |
| `:system-length N` | score | whole piece | Pulses per system. Replaces `:steps-per-system` on `piece`. |
| `:breaks (POS ...)` | score | none | Start a new system at each position, for systems of different lengths. With `:system-length`, both apply. |
| `:caption STRING` | score | none | A caption under the score (on its own page; a document sets its own). |

### Labels

| Option | Level | Default | Meaning |
|---|---|---|---|
| `:labels long/short/first-long` | score, group | `first-long` | Which label to print: always the long one, always the short one, or the long one on the first system and the short one after (LilyPond's way). |
| `:short STRING` | group | the long label | The short label. |

### Above the grid

| Option | Level | Default | Meaning |
|---|---|---|---|
| `:cycle-numbers yes/no` | score | yes with a colotomy | A row with the cycle number, at the start of each cycle. |
| `:pulse-numbers yes/no` | score | `yes` | A row with the pulse number within the cycle (or within the piece, without a colotomy). |
| `:numbering gong-last/gong-first` | score | `gong-last` | How pulses are numbered: 1 to N with the gong on N (Gold), or with the gong on 1 (Tenzer). Only the printed numbers change. |
| `:pulse-label STRING` | score | none | A label at the left of the pulse row, e.g. "Beats". |

With both, the cycle row is above the pulse row. Lines between columns
are drawn by layout's decision: a light line at every pulse, a heavier
one at every cycle boundary (the gong).

With `gong-first`, our pulse k of an N-pulse cycle is printed as
(k mod N) + 1, so the gong on pulse N is printed 1 and the pickup of a
piece that opens on the gong is printed 1 as well.

### Text in the grid

| Option | Level | Default | Meaning |
|---|---|---|---|
| `:note-names yes/no` | score, group | `no` | Write each note's or stroke's name in its cell. Replaces `show-names` on instruments. |
| `:pattern-names none/short/long` | score, group | `none` | Write pattern names over the notes (see below). |
| `:pattern-level N` | score, group | `0` | Which level of nested patterns to name: 0 for patterns used directly in the part, 1 for patterns inside those, and so on. |
| `:fill colour/none` | score, group | `colour` | `none` draws the names alone, without a coloured box (JSON `fill: null`). Needs `:note-names yes`. |
| `:holds none/dash` | score, group | `none` | `dash` writes "-" in every step a note is held, as in a sung line. |

By default a note is only a colour, for strokes too. This changes the
current default, where strokes show their names (ADR 0019): a gong
group now asks for names with `:note-names yes`.

**Which name a note shows.** A degree or stroke has a display form
(`:display "nang"`) and may have a damped form (`:damped "na'"`, see the
language note). A note shows its damped form when it lasts no longer
than one column of the grid, and its open form otherwise. In Baris this
gives every syllable of Tenzer's figure: the reyong's held notes are
open, its single steps damped, and the ugal's one-pulse notes open.
Without a damped form, the display form is used for both.

### Colour

| Option | Level | Default | Meaning |
|---|---|---|---|
| `:scheme NAME` | score, group | `by-degree` | How notes are coloured (04, "Note style"). |
| `:palette NAME` or `:palette (COLOUR ...)` | score, group | `pastel1` (ADR 0021) | The colours, by name or as a list of `"#rrggbb"`. |
| `:colors ((DEGREE COLOUR) ...)` | score, group | none | Colours for particular degrees, e.g. `((ding "#000000"))`. |

These are the settings of `make-style` (04), moved into the notation;
this answers 04's open question about a `style` form. Strokes stay grey.

### Size

| Option | Level | Default | Meaning |
|---|---|---|---|
| `:font-size LENGTH` | score | `"8pt"` on its own page; the document's text size in a document | The base text size. |
| `:cell-width LENGTH`, `:cell-height LENGTH` | score | `"2em"`, `"2em"` | The grid cell. Equal sizes make square notes. |

A LENGTH is a string holding a Typst length: a number and a unit
(`"8pt"`, `"2em"`, `"4mm"`), checked by the reader. Sizes in `em`
scale with `:font-size`. In a Typst document `:font-size` is normally
left out, so the score takes the document's size (05, template point
7).

### Rows

| Option | Level | Default | Meaning |
|---|---|---|---|
| `:rows notes/parts/single` | score, group | `notes` | `notes`: one row per key or stroke used (the lanes, as now). `parts`: one row per part, notes told apart by their names. `single`: all the group's parts on one row (a composite). |

With `:rows parts`, a group's body can give each part a row label:

```scheme
(group "Kendang lanang" :rows parts
  (lanang-lh :label "LH") (lanang-rh :label "RH"))
```

A body item is a part name, or a list of a part name and options; the
only option for now is `:label`, which defaults to the part's name.
With `:rows single`, the group's parts must not sound at the same time
in a way that would put two notes in one cell (an error otherwise).

## Pattern names over the notes

With `:pattern-names short` (or `long`), each use of a pattern at the
chosen level is named once, written over the coloured notes and
spanning the pattern's columns:

```
 Pemade │■■ ■■■ ■ ■■■ ■ ■ ■ ■■ ■│■ ■■ ■ ■■■ ■■ ■ ■ ■■│
        │        norot          │        norot        │
```

- Layout gives each group a list of **overlays**: the columns and rows
  they cover, the text, and whether they continue from the previous
  system. The template places each as one cell spanning those columns
  and rows, with the text centred.
- An overlay spans the rows of the group. Its text is near-black, on a
  small white, slightly transparent box, centred over the span, so it
  can be read over notes of any colour.
- Overlays from several parts of a group that are identical (same
  start, length and text) are merged into one. In Jaya Semara the
  polos and sangsih carry the same names over the same pulses, so each
  name is written once. Different names overlapping in one group are
  an error, naming the parts and the position.
- One level is named at a time (`:pattern-level`).
- With `:note-names yes` as well, the overlay is drawn on top of the
  note names.
- Overlays cut by a system break are split like notes; the later piece
  is marked `continued` and its text is written again.

## Rules

- Score names are unique in a file. Group labels need not be.
- Every part a group names must exist: written parts by their names,
  generated parts as above.
- Within one score a part is in at most one group, and all the pitched
  parts in a group play the same instrument (ADR 0011). The same part
  may appear in several scores.
- A group with no parts, an unknown option, an option at the wrong
  level, or a bad value (an unknown palette, a colour that is not
  `"#rrggbb"`, a length without a unit) is an error.
- `:from` must come before `:to`, and both must lie in the piece.
- `:rows parts`, `:rows single` and `:fill none` need `:note-names yes`
  on the group: without names those rows would not show pitch. It is
  an error otherwise.
- A group label may be empty (`""`); Baris's kempli and gong block has
  only row labels.

### Files without a score

A file with no `score` form gets a default score: every part, written
and generated, in its own group, in source order, labelled with its
name, with every option at its default.

### Choosing a score

`notasi render jaya.nts --score kotekan` prints the score named
`kotekan`. A Typst document refers to a score the same way, by file and
name (06). Without `--score`, the first score in the file is printed.

## Examples

From `../targets/2026-11-21-jaya-semara-pangecet.nts`: a full score, and an
excerpt that shows only the kotekan against the pokok, for one pass of
the melody.

```scheme
(score full :pattern-names short :palette pastel1
    :font-size "8pt" :cell-width "2em" :cell-height "2em"
  (group "Gangsa pemade" :short "Pem." :subtitle "norot"  polos sangsih)
  (group "Ugal"          :short "Ug."   ugal)
  (group "Panyacah"      :short "Pny."  panyacah)
  (group "Jublag"        :short "Jub."  jublag)
  (group "Jegogan"       :short "Jeg."  jegogan)
  (group "Gong, kempli"  :short "G. K." :note-names yes  gong kempli))

(score kotekan :title "Norot kotekan against the pokok"
    :from (1 1) :to (1 8) :labels long
    :pattern-names short :pattern-level 1 :cycle-numbers no
  (group "Gangsa pemade" polos sangsih)
  (group "Jublag" jublag))
```

In the full score, the pemade notes carry "norot" over each pass of the
melody, and the gongs show their letters. In the excerpt, the pemade
notes carry the names of the 2-pulse figures (level 1), and the other
parts are not printed. The moved figures carry the names given at their
use (`(@ polos-1 :step -1 :short "6")`), so polos and sangsih show the
same names, "1", "6", "3", "2", and each is written once.

From `../targets/2026-11-21-baris.nts`, Tenzer's layout and one of his sung lines:

```scheme
(score full :fill none :note-names yes :numbering gong-first
    :pulse-label "Beats" :breaks ((1 3))
    :caption "Notation of reyong and kendang parts, with gong, kempur, kempli and calung (core melody)."
  (group "Reyong" :subtitle "sangsih, polos"  sangsih polos)
  (group "Ugal" :subtitle "main melody" :rows parts  ugal)
  (group "Calung" :subtitle "core melody" :rows parts  calung)
  (group "" :rows parts  (kempli :label "Kempli") (gong :label "Gong & Kempur"))
  (group "Kendang lanang" :rows parts
    (lanang-lh :label "LH") (lanang-rh :label "RH"))
  (group "Kendang wadon" :rows parts
    (wadon-lh :label "LH") (wadon-rh :label "RH")))

(score polos-alone :fill none :note-names yes :numbering gong-first
    :pulse-label "Beats (Clap)" :breaks ((1 3)) :holds dash
    :caption "Singing the reyong polos part alone"
  (group "Reyong/Polos" :rows parts  polos))
```

## Implications for layout, JSON and the template

### Layout

- `(layout-score piece score #:key ...)` replaces `layout-piece`: one
  figure per score. The style is built from the score's colour options.
- Layout chooses the step for the score (the largest time dividing
  every start and end it prints, every pattern span edge, and the
  pulse) and converts the piece's rational times to integer columns.
  The JSON writer refuses rationals, so a time left unconverted fails
  loudly.
- Layout cuts the excerpt (`:from`, `:to`); a note that started before
  it arrives `continued`, as at a system break. Numbers stay absolute.
- Layout works out every header number and every line (none, pulse,
  cycle) for every column, so the template does no counting. With
  cycles and pickups, the template's current pulse arithmetic would be
  wrong.
- With a pickup, the first system starts with it (as LilyPond's
  `\partial` sits in the first bar).
- Labels: layout puts the long or short label in each system's group as
  `:labels` says. `label_width` is measured from the labels printed.
- Rows: with `:rows notes` a group's rows are its lanes, as now; with
  `parts` each part is one row, labelled; with `single` all parts share
  one row. An event's `lane` is then its row.
- Systems are cut at every `:breaks` position as well as every
  `:system-length`.
- Note text: the damped or open form by the one-column rule; with
  `:holds dash`, layout adds a "-" event in every held step.
- Overlays: layout finds the pattern spans at the chosen level in each
  group's parts, merges identical ones, and turns them into columns and
  rows.

### JSON contract, version 2

All of this is a new contract version (05: the template and golden
files change in the same PR):

```json
{
  "version": 2,
  "title": "Jaya Semara: pangecet",
  "subtitle": null,
  "steps_per_pulse": 4,
  "sizes": { "font_size": "8pt", "label_width": "9.3em",
             "lane_width": "2.0em", "cell_width": "2em",
             "cell_height": "2em" },
  "systems": [
    {
      "start": 0,
      "steps": 68,
      "header": {
        "cycles": [{ "column": 4, "text": "1" }],
        "pulses": ["16", null, null, null, "1", null, null, null, "2"]
      },
      "lines": ["none", "none", "none", "none", "cycle", "none", "none",
                "none", "pulse"],
      "groups": [
        {
          "label": "Gangsa pemade",
          "subtitle": "norot",
          "lanes": ["u3", "e3", "o3", "i3", "a2"],
          "voices": [ { "name": "polos", "events": [ ... ] } ],
          "overlays": [
            { "start": 4, "dur": 32, "row": 0, "rows": 5,
              "text": "norot", "continued": false }
          ]
        }
      ]
    }
  ],
  "caption": null
}
```

(Arrays shortened.) Compared with version 1:

- `subtitle`, `sizes.font_size`, `sizes.cell_width`,
  `sizes.cell_height` are new; `step_width` and `row_height` become the
  cell sizes.
- `header` and `lines` are new; `header.cycles` or `header.pulses` is
  `null` when that row is not shown; `header.label` holds the
  `:pulse-label`. The numbers in `header.pulses` already follow
  `:numbering`.
- `lanes` becomes the row labels: keys, strokes or part labels.
- `caption` carries the score's `:caption`.
- `overlays` is new on each group.
- An event's `text` is `null` unless note names are shown.

### Template

- Draws the header rows and lines from the JSON instead of computing
  pulse numbers.
- Draws overlays as cells spanning their columns and rows, with the
  text centred over the notes.
- Sets the text size from `sizes.font_size` in a standalone figure;
  in a document it is left to the document.

### Elsewhere

- `render-piece` and `notasi render` take a score name (`--score`).
- Golden files: one per example and score; a file with only the default
  score keeps its plain name (`tenzer1.json`), others are
  `NAME.SCORE.json`.
- Typst documents (06): a manifest entry is for a snippet or file and a
  score.
- ADR 0019's default (names on strokes) and 0021's (palette fixed in
  Guile) change: names are off unless asked for, and the palette can be
  chosen in the score.

## Open questions

The questions this note raised are settled for this iteration in
`2026-11-21-iteration-2.md` ("Decisions", "Score"), and folded into
the sections above: the first score is the default; overlays are
near-black on a light box, identical ones merged, different ones in one
group an error, drawn over note names, repeated after a system break,
one level at a time; cycle numbers appear once per cycle; a pattern's
use may carry its own names; Tenzer's layout is copied in information,
not in every detail; rows that hold several pitches need note names;
the open and damped forms follow the grid.

### Later

- Systems one cycle long: `:system-length (cycles 1)`.
- The `(text STRING)` form of `01-notation.md`: out of the notation;
  captions are `:caption`, and Typst documents (06) do the rest.
- Marking damping in the music, instead of deriving the name form from
  the grid.
- Instrument pictures, "etc." at line ends, colons after labels,
  systems side by side.
- A level above groups (brackets); tagged versions of the music; more
  colour schemes (by part, by octave).
